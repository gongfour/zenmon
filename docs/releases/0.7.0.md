# zenmon 0.7.0

Explore any Zenoh application, verify what you recorded, and inspect it without
reconnecting to the network.

- **Offline dashboard:** `zenmon tui --trace ./trace` opens a capture file or
  store. Browse keys, compare payloads, inspect attachments, plot numeric fields,
  and navigate by message or second. No network session is opened.
- **Indexed recordings:** payloads live in a temporary disk spool; time/key
  indexes let the viewer load recent history instead of replaying every earlier
  message on each seek. Limits: 1 million records, 2 GiB decoded spool, 10,000
  keys, 16 MiB per record. Initial indexing still scans the input.
- **Integrity checks:** `zenmon trace verify ./trace` reports malformed records,
  invalid binary fields, and incomplete compressed frames with file/line details.
  This checks stored data, not network delivery or missing segments.
- **Generic scenarios:** trigger attachments and key/payload/attachment predicates
  describe stop conditions without application-specific task conventions.
- **Explicit interruption:** Ctrl+C preserves the partial scenario episode,
  skips the remaining settle period, reports `interrupted`, and exits 130.
- **No-router demo:** `python3 scripts/demo.py --output demo.ndjson` creates a
  synthetic recording for the offline dashboard.

## Migration from 0.6

`scenario --task` has been removed. Applications should implement their own
adapter for request keys, metadata, and response correlation, or use the generic
flags directly. For a protocol that returns `request_id` in its response:

```bash
zenmon --json scenario \
  --pub demo/job/request '{"operation":"inspect"}' \
  --att '{"request_id":"example-001"}' \
  --until-key demo/job/response \
  --until-payload /request_id '"example-001"' \
  --for 10s
```

Choose a fresh correlation ID for each real request; the example ID is illustrative.
`meta.ended_reason` now uses `condition_matched` instead of `task_response`.
It can also be `window_elapsed`, `interrupted`, or `stream_closed`. An ordinary
recording window expiring remains exit 0; an unexpectedly closed observation
stream exits 3. Silence alone is not a stream-close event.

Existing v1/v2 captures remain readable. New captures retain millisecond receiver
timestamps. Verification and the offline dashboard require complete records and
compression frames; use `trace read` for live-tolerant inspection of active stores.
